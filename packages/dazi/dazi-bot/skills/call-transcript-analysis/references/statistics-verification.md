# 统计数字对账纪律（文本分析报告必读）

## 背景：2026-08-12 电招外呼话术手册案例

分析 278 通含 transcriptionText 的外呼对话、产出 HTML 话术手册时，核验代理发现 3 处关键数字无法从源数据复现：

| 手册数字 | 实际复算 | 差异原因 |
|---|---|---|
| 加微信 396 次 | 明确收口话术 **118 条**（加你微信59+加您微信37+加我微信11+通过一下11）；含"微信"二字语句 367 条 | 原脚本把多个同义词变体 + 上位词重复累加，口径虚高 |
| 考核定级 31 次 | **27 次** | 关键词集与复算脚本不一致 |
| 开场"自报家门+问找工作" 81 通（29%） | **79 通（28%）** | 正则分类边界漂移；79/278≈28.4% |

其余数字（下载APP 144、填简历 92、体检 76、就近安排 152、发单 46、服务费 73、工作类型 1061、位置 183、年龄 254、经验 108、黄金问句 24）均精确复现。

**根因**：关键统计散落在多个一次性 Python 脚本里，每个脚本的关键词集、计数口径（按语句 vs 按通话 vs 按动作归类）互不一致，最后把各脚本的数字手填进 HTML。

## 硬规则

1. **单一权威脚本 + 中间事实源**：所有关键统计由同一个脚本、一套固定关键词集产出，中间结果落 JSON（如 `_dialogue_split.json`）作为唯一事实源。HTML 报告里的每个数字只准从这份 JSON 派生，禁止凭印象手填。
2. **固定并区分计数口径**：每条统计必须明确口径——「语句命中 N」（员工发言中含关键词的语句数）vs「通话命中 M」（多少通电话至少提及一次）vs「明确动作 X」（收口句式归类，如"加X微信/通过一下"）。三者可能差异巨大（本案例：147 语句 / 116 通话 / 118 明确收口 / 367 含微信）。
3. **同义变体先归类再计数**："加你微信/加您微信/加我微信/通过一下"是同一动作的变体，先归并到动作级再统计；不要把变体与上位词（"微信"）混成一个数。
4. **占比自洽校验**：任何百分比必须能整除复核（79/278≈28.4%→写"28%"）；分类计数之和应≈样本总量（本案例四类开场合计 229 ≠ 278，说明分类有漏，需复核而非硬凑成 278）。
5. **交付前强制数字对账**：HTML/文档定稿前，用与生成完全一致的关键词集从源数据重算所有出现的数字，再 Grep 报告全文逐一核对；发现一处不符，立即以重算为准修正，并顺带自查是否还有其他硬编码数字。

## 对账复现命令模板

```python
# 加载中间事实源（或源 xlsx），固定关键词集，输出各口径计数
import json
with open('_dialogue_split.json', encoding='utf-8') as f:
    data = json.load(f)
spk2 = data['spk2']  # 员工发言语句列表

def count(kws):  # 语句命中口径
    return sum(1 for u in spk2 if any(k in u for k in kws))

print('加微信明确收口(118):', count(['加你微信','加您微信','加我微信','通过一下']))
print('含"微信"(367):', count(['微信']))
print('下载APP(144):', count(['一点通','下载','应用商店']))
```

报告定稿后：`grep -nE "数字1|数字2|..." 报告.html` 逐一核对；然后用 Counter 精确复算高频整句（避免近义句被重复计数）。
