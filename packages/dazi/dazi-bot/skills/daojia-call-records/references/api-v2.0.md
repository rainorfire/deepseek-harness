# 通过用户ID获取通话记录(含录音文本)接口 v2.0 — 详细规范

飞书文档《通过用户ID获取通话记录(含录音文本)接口 v2.0》要点沉淀（2026-08-12 实测）。

## 接口信息

| 项 | 值 |
|---|---|
| 接口地址（生产） | `GET https://call.daojia-inc.com/admin/heli/call-event/v2/with-text/list/ajax` |
| 鉴权 Header | `X-Cli-Agent-Token: <token>` + `X-Cli-Agent-Type: openClaw` |
| Token 位置 | 记忆文件 `~/.dazi/projects/-Users-chenyujia-Documents------dazi/memory/daojia_api_token.md`（20天前沉淀仍有效） |

## 请求参数

| 参数 | 说明 |
|---|---|
| `userIds` | urmId，多值逗号拼接。**实测建议一次只查一个人**，翻页更稳、不串页 |
| `talkTimeMin` | 通话时长阈值（秒），返回 `talkTime` > 此值的记录。例：30 → 只返回接通超30秒的通话 |
| `page` | 页码，从 1 开始 |
| `rows` | 每页条数，**上限 100**（取 300 条需翻 3 页，勿传 300 会被拒/截断） |
| `visitBusId` / `callSheetId` | 可选维度，按需传 |

排序固定 `id desc`（最新在前），取「最近 N 条」直接翻前几页即可。

关键字段：`talkTime`（通话秒数，字符串）、`ring`（振铃）、`begin`/`end`（接通/挂断）、`callNo`（主叫）、`calledNo`（被叫）、`state`（接通状态）、`transcriptionText`（录音转写）。

## 录音文本数据范围（重要）

- **2026-08-05 之后**的通话才含 `transcriptionText`，历史数据不转文本。
- **通话 <5 秒不转**文本。
- 筛选 >30s 的近期通话基本都带文本（实测第一条 81 秒通话文本完整）。

## 坑与经验

- 鉴权失败先查 Token 是否过期（20 天前沉淀的 Token 实测仍有效）。
- Token 含特殊字符时严禁 `python3 -c "..."` 内联跑，必须写成 .py 文件或环境变量传。
- 输出 CSV 用 `utf-8-sig` 编码，Excel 打开不乱码。
- 校验口径：条数=300 / `talkTime`>30 / `state`=接听(成功) / `begin` 非空。
- 沉淀脚本：工作目录 `_query_call_records.py`（`test` 模式验证凭证，`all` 模式全量，后台跑）。
