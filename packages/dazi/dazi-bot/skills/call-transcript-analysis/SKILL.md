# 外呼转录文本分析 → 话术整理（Call Transcript Analysis）

分析通话/外呼转录文本（CSV 中 transcriptionText 字段），提炼外呼话术、流程环节与异议处理，输出可复用的话术整理文档。

## 典型场景
- 智博外呼记录 CSV（`通话记录_接通超30秒.csv` / `超60秒.csv`），电招员工引导家政劳动者在「阿姨一点通」补全个人信息
- 任何「一个角色是公司员工，在引导/销售/服务另一个角色」的对话转录整理

## 数据特征（智博外呼 CSV 已知结构）
- 编码：**utf-8-sig**（带 BOM），用 `encoding='utf-8-sig'` 读取，否则表头第一个字段会带 \ufeff
- 字段：`_员工, _urmId, id, callSheetId, callType, callNo, calledNo, ring, begin, end, talkTime, state, agentName, agent, callSystemName, busSystemFlag, userId, visitBusId, transcriptionText`
- **发言者约定：发言者1 = 劳动者/客户，发言者2 = 电招员工**（分析话术只看发言者2）
- 转录文本是 ASR 语音识别结果，**错别字极多**（如「阿姨一点通」写成「吖一点通/阿E一点通」「天鹅到家」写成「天猫到家/天融到家/金融到家」），引文核实必须用模糊匹配而非精确匹配
- 用 `csv.DictReader` 统计行数（`wc -l` 会多算表头且可能因内容换行偏差）

## 分析工作流（五步）

### 1. 结构盘点
统计：总行数、员工分布（按 `_员工`）、有转录文本条数、各员工转录条数、时长分布。确认转录覆盖率（如 426/1800），先向用户交代数据规模。

### 2. 关键词定位环节
对全部转录文本做关键词命中统计，定位话术环节分布。家政场景高频词：微信、简历、年龄、身份证、阿姨、证书、手机号、培训、体检、视频、资料、面试、完善、照片、上传、实名、头像、健康证、验证码。

### 3. 场景抽样精读
按场景抽完整对话样例精读：开场白、需求确认、年龄审核、加微信、引导下载APP、补全简历/头像/人脸识别、异议处理（收费/黑中介/拖延）、拉群看单。同时对比不同员工话术风格差异。

### 4. 归纳话术文档
输出 Markdown 文档，结构：数据概况表 → 高频关键词表 → 话术流程环节（每环节含真实引文）→ 员工风格对比表 → 可复用转化要点。**每个环节的引文必须带员工来源**。

### 5. 验证（交付前必做）
- 统计数字：总行数、员工分布、转录条数、关键词命中数，用脚本逐项核对源 CSV
- **统计口径陷阱**：「包含某词」≠「以某词开头」。例：含「天鹅到家」366条 vs 以「天鹅到家来电」开场203条，数字完全不同。写文档前先确定口径，写完后精确核对该口径的实际值
- **引文核实**：所有引号引文必须能在源转录中找到真实原话（ASR 错别字多，用模糊子串匹配），凭印象写的引文几乎必然失真，要替换成真实措辞
- 发言者角色：抽样核对「发言者2」确为电招员工自称

## 关键坑（务必遵守）
1. **引文失真**：转录是 ASR 结果，凭记忆/印象引述的话术与原文措辞不一致（如「你先加微信把简历弄好」原文实为「先给您把简历这些都弄好，到时候你回来好接单」）。所有引文必须模糊匹配源文本逐句核实后落稿。
2. **统计口径**：写「N条以X开头」前必须定义精确口径（开头40字符内含/首行含/全程含），并跑脚本按该口径精确计数，数字不对立即修正。
3. **验证子进程可能因权限阻塞**：独立验证 Agent 可能因审批被拦截跑不了脚本，此时应在主会话内直接跑核对脚本完成验证，不要留「验证中」的悬念。
4. **CSV 编码**：utf-8-sig，别用默认 utf-8。
